In my current project, since we are deploying LLM workloads using Haystack and vLLM on AWS, we focus on a few important SLIs and SLOs to ensure application reliability and performance.

Our primary SLIs are:

1. **Availability:** We monitor whether our application endpoints are available and responding to incoming requests.

2. **Request Success Rate:** We track the percentage of successful API requests against the total number of requests.

3. **Latency:** We monitor API response time, particularly the 95th and 99th percentile latency, to understand how quickly the application responds.

4. **Throughput:** We monitor the number of incoming requests the application can handle within a given time.

5. **LLM Inference Performance:** Since we are working with LLM workloads, we also consider Time to First Token and token generation speed.

Based on these SLIs, we define our SLO targets. For example, we can target 99.9% application availability, 99.5% request success rate, and keep API latency within agreed thresholds for a defined workload.

We use Prometheus, Grafana, and CloudWatch to monitor these metrics and configure alerts whenever there is a deviation from the expected thresholds.

We also monitor CPU, memory, and GPU utilization to understand resource consumption and identify scaling requirements.

For example, when incoming request traffic increases, we monitor request count per target and use that information to scale our Haystack and vLLM infrastructure.

Our overall objective is to maintain application availability, minimize request failures, and provide consistent response times even during increased traffic.
