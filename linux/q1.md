A **daemon** is a background process that usually runs continuously and performs a specific task or provides a service. For example, `sshd` handles SSH connections, `nginx` handles web traffic, and `dockerd` manages Docker containers.

A **service** is a system or application functionality that is managed by a service manager such as `systemd`. For example, `nginx.service` is managed by systemd, and behind that service, one or more nginx processes actually perform the work. So, in simple terms, **the service is the managed functionality, while the daemon is the background process doing the work**.

An **orphan process** occurs when a parent process terminates while its child process is still running. Linux then re-parents the child to PID 1, or to an appropriate subreaper, so the child can continue running normally.

A **zombie process** occurs when a child process has already finished execution, but its parent has not yet collected the child's exit status using `wait()` or `waitpid()`. The process is no longer running, but the kernel temporarily keeps its process-table entry.

The easiest way to remember the difference is:

**Orphan → Parent dies first, child is still running.**

**Zombie → Child dies first, but the parent hasn't cleaned up its exit status yet.**

# Linux Kernel and Operating System

The **Linux kernel** is the core component of the Linux operating system. It acts as an interface between applications and the hardware. Applications don't directly interact with hardware; they communicate with the kernel through **system calls**.

The kernel is responsible for managing important system resources such as:

- CPU
- Memory
- Processes
- Storage
- Networking
- Hardware devices

For example, if an application needs to **read a file from disk** or **allocate memory**, it requests the kernel to perform that operation.

## Kernel vs Operating System

The **kernel** is the core part of the operating system, whereas the **operating system** is the complete environment.

The operating system includes:

- Linux kernel
- System libraries
- Utilities
- Services
- Shells
- Package managers
- Other system tools

### Example

**Ubuntu** or **RHEL** is a complete Linux distribution. It contains the Linux kernel along with tools such as:

- Bash
- systemd
- Package managers
- Libraries
- Other utilities

So technically:

> **Linux refers to the kernel, while Ubuntu and RHEL are Linux distributions built around the Linux kernel.**


# Process vs Thread

## What is a Process?

A **process is a running instance of a program**.

When I start an application, Linux creates a process for that application. A process has its own **memory address space** and resources such as:

- Open files
- Environment variables
- Process ID (PID)

## What is a Thread?

A **thread is a smaller unit of execution within a process**.

A single process can have multiple threads, and those threads **share the process's memory and resources**, but each thread has its own:

- Stack
- Registers
- Execution state

## Process vs Thread

| Process | Thread |
|---|---|
| A running instance of a program | A unit of execution within a process |
| Has its own memory address space | Shares memory with other threads in the same process |
| Has its own resources | Shares most resources with other threads |
| More expensive to create and manage | Less expensive to create and manage |
| Communication between processes requires mechanisms like IPC | Threads can communicate through shared memory |
| Failure usually affects that process | A thread failure can potentially affect the entire process |


# Linux File System

The **Linux file system** is a hierarchical structure where everything starts from the **root directory `/`**. Unlike Windows, Linux doesn't have separate drive letters like `C:` or `D:`. All files, directories, devices, and mounted filesystems are organized under `/`.

There are several important directories, each having a specific purpose.

## What is Soft link and hard link
A **hard link** is another name for the same file. It points to the **same inode** as the original file, so both filenames refer to the same underlying data. Because they share the same inode, if I delete the original filename, the hard link will still work because the data is still referenced by the hard link.

A **soft link**, also called a **symbolic link**, is a separate file that points to the **path of another file**. It has its own inode. If the original file is deleted or moved, the soft link can become a broken link because the path it points to no longer exists.

The main differences are that **hard links share the same inode and generally cannot cross filesystems or point to directories**, while **soft links have their own inode, can cross filesystems, and can point to both files and directories**.

So, the easiest way to remember it is:

**Hard link → same inode**

**Soft link → points to a path**
