A **daemon** is a background process that usually runs continuously and performs a specific task or provides a service. For example, `sshd` handles SSH connections, `nginx` handles web traffic, and `dockerd` manages Docker containers.

A **service** is a system or application functionality that is managed by a service manager such as `systemd`. For example, `nginx.service` is managed by systemd, and behind that service, one or more nginx processes actually perform the work. So, in simple terms, **the service is the managed functionality, while the daemon is the background process doing the work**.

An **orphan process** occurs when a parent process terminates while its child process is still running. Linux then re-parents the child to PID 1, or to an appropriate subreaper, so the child can continue running normally.

A **zombie process** occurs when a child process has already finished execution, but its parent has not yet collected the child's exit status using `wait()` or `waitpid()`. The process is no longer running, but the kernel temporarily keeps its process-table entry.

The easiest way to remember the difference is:

**Orphan → Parent dies first, child is still running.**

**Zombie → Child dies first, but the parent hasn't cleaned up its exit status yet.**
