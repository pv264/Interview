# Docker Production Best Practices

In production, we strictly follow Docker best practices to ensure security, efficiency, and maintainability:

1.  **Base Images:**
    * Use **minimal** base images (e.g., Alpine, Distroless) to reduce attack surface.
    * Use **pinned versions** (e.g., `node:18.16.0-alpine` instead of `node:latest`) for deterministic builds.

2.  **Image Optimization:**
    * Implement **Multi-stage builds** to discard build dependencies and drastically reduce the final image size.
    * **Minimize layers** by combining commands (e.g., `RUN apt-get update && apt-get install...`).
    * Leverage the **Docker build cache** properly by ordering instructions from least to most frequently changed.

3.  **Security:**
    * **Avoid Root User:** Create and switch to a non-root user (`USER appuser`) inside the Dockerfile.
    * **Secrets Management:** Ensure secrets and credentials are **never baked** into the image; inject them at runtime via environment variables or secret managers.
    * **Vulnerability Scanning:** Scan images for CVEs using tools like **Trivy** or **Clair** before deploying to the registry.

4.  **Context Management:**
    * Use `.dockerignore` to exclude unnecessary files (like `.git`, `node_modules`, `local-secrets`) from the build context.


    ## 2 What happens when you execute `docker run`?

**Step 1: CLI to Daemon Communication**
When we run `docker run`, the Docker CLI sends the request to the Docker daemon. 

**Step 2: Image Verification & Pulling**
The daemon first checks whether the required image is available locally. If it's not, Docker pulls the image from a registry such as Docker Hub. 

**Step 3: Container Creation & Storage Layer**
Next, Docker creates a new container by adding a writable layer on top of the read-only image layers. 

**Step 4: Isolation & Resource Limits (Namespaces & cgroups)**
It then sets up Linux namespaces to isolate the container's processes, network, filesystem, and hostname, and applies cgroups to manage CPU and memory limits if configured. 

**Step 5: Networking & Volumes**
Docker configures networking by connecting the container to a Docker network and setting up any port mappings. If volumes are specified, they are mounted into the container. 

**Step 6: Starting the Main Process**
Finally, Docker starts the container's main process (PID 1), defined by the image's `CMD` or `ENTRYPOINT`. As long as that main process is running, the container remains in the running state.

## What is the difference between a Docker Image and a Docker Container?

### Docker Image
A Docker image is a template that contains everything needed to run an application, such as the application code, runtime, libraries, dependencies, configuration, and startup command. It serves as a blueprint for creating containers. 

### Docker Container
A Docker container is a running instance of that image. When we execute `docker run`, Docker creates a container by adding a writable layer on top of the image, sets up isolated resources such as processes and networking, and starts the application's main process. 

**Key Takeaway:** One image can be used to create multiple independent containers.
